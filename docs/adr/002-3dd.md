# ADR 002 — Proceso 3DD (SDD + BDD + TDD)

Estado: aceptada (permanente) · Fecha: 2026-10-05

## Contexto
Los outputs audiovisuales no se pueden dar por buenos solo con tests; el gusto es humano.

## Decisión
Claude escribe specs desde la intención del usuario, los escenarios BDD se convierten en tests en rojo y luego en código; el usuario califica el output y la nota vuelve a la spec. Ver docs/specs/README.md.

## Consecuencias
Lo que el usuario critica y ningún test detecta es un falso negativo del sistema: genera un escenario nuevo. Ningún output audiovisual está hecho sin nota.
